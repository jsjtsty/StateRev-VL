# Tracking-algorithm study, G1 pre-registration

Written 2026-09-23, **before any model was run on this data.** Data: `outputs/tracking_algo_v1/data/items.jsonl`, generated by `scripts/tracking_algo_generate.py --seed 20260923`, renderer `staterev/shellsim.py`, algorithm family `staterev/shortcuts.py`.

## Motivation

On the existing VET-Bench cup data, Qwen3-VL-8B's native answers at t>=3 agree with the "position-anchored last-touch" shortcut (`last_touch_init`) 0.54 [0.45, 0.63], versus 0.35 with ground truth and 0.35 under an answer-permutation null. That shortcut was chosen post hoc from 9 candidates, so it has to be confirmed on new data where shortcut and ground truth are decorrelated by design.

## Data

| set | cups | cups visible? | swaps k | n | design |
|---|---|---|---|---|---|
| opaque3 | 3 | opaque | 2–6 | 300 | per k: 30 with shortcut = GT, 30 with shortcut != GT; init position balanced |
| transp3 | 3 | transparent | same sequences as opaque3 | 300 | observability control |
| k1 | 3 | opaque | 1 | 30 | perception sanity check |
| opaque4 / opaque5 | 4 / 5 | opaque | 3, 5 | 120 each | same agree/disagree balancing |

- Frames are 448×336, sampled at 4 fps and fed as a video.
- Prompt variants:
  - `init`: the text states the ball's starting cup. **This is the primary variant**, because it removes the confound of whether the model perceived the starting position.
  - `vis`: no starting position in text, VET-Bench style. Secondary.

## Answer extraction

Each option (A, B, C, …) is scored by its next-token logit right after the generation prompt, with thinking disabled where the chat template allows. The answer is the argmax over option letters. A short greedy continuation is also logged to check the answer format.

## Primary hypotheses

All computed per model on opaque3, `init` prompt. Each video is an independent unit, so percentile bootstrap is used (10k resamples). α = 0.05, one-sided, no multiplicity correction across models; the gate below is the decision rule.

- **H1a**: accuracy on the disagree subset (shortcut != GT, n=150) is **below 1/3**.
- **H1b**: on the disagree subset, P(answer = shortcut) exceeds its answer-permutation null (the model's answers permuted across disagree items, 10k permutations) **and** exceeds P(answer = GT).
- **H1c**: accuracy on the agree subset exceeds accuracy on the disagree subset.
- **H2** (observability): on transp3, accuracy on the disagree subset is above 1/3, and higher than on opaque3's disagree subset.

## Secondary analyses (exploratory, reported as such)

- Agreement of the answers with every member of `staterev/shortcuts.FAMILY`, to check whether a different shortcut explains the data better.
- Effects by k, by number of cups (opaque4/5, chance 1/4 and 1/5), under the `vis` prompt, and in the Thinking model.
- Answer position bias.

## Decision gate G1

- **Pass**: H1a and H1b hold in at least 3 of the evaluated non-thinking models. Then proceed to mechanism localization (G2).
- **Fail**:
  - If models are at chance on both subsets with no shortcut preference, the shortcut story is dropped.
  - If a different family member dominates, that member becomes the hypothesis, but only as an exploratory result that needs its own confirmation set.

## Addendum A: minimal-pair causal test

Written 2026-09-23, before any model was run on these pairs.

Data: `outputs/tracking_algo_v1/data_pairs/` (`scripts/tracking_algo_pairs.py --seed 20260924`). There are 120 bases, each 3 cups, opaque, k = 3–5. For each base, three variants insert exactly one extra swap:

- `gt_only`: changes the GT answer but not the shortcut answer.
- `sc_only`: changes the shortcut answer but not the GT answer.
- `neither`: changes neither (length-matched noise baseline).

Measure: the flip rate, P(answer on variant != answer on base), per variant kind. Prompt = `init`.

- **H3a (shortcut algorithm)**: flip(sc_only) > flip(gt_only). Tested with a paired bootstrap over bases, one-sided α = 0.05.
- **H3b**: flip(gt_only) − flip(neither) is small, meaning its 95% CI includes 0 or is below 0.10.
- Under correct tracking, flip(gt_only) would be about 1 and flip(sc_only) about flip(neither).
- A model supports the shortcut algorithm causally if H3a holds and flip(sc_only) − flip(neither) > 0 (CI above 0).

## Addendum B: colored-cups set (retrieval control)

Written 2026-09-23, before any model was run on this set.

`colored3` uses the same 300 sequences as opaque3, but each cup has a distinct color (blue / green / yellow, randomly assigned per video). The prompt says "cups of different colors". The task then becomes solvable by binding the ball to a cup color at the start and finding that color at the end, with no composition of swaps needed. The cups stay opaque and the ball stays occluded.

- **H4**: accuracy(colored3) > accuracy(opaque3), paired bootstrap over sequences, one-sided α = 0.05; `init` prompt primary.
- Under a composition-limitation account, colored3 should approach transp3. If colored3 stays at chance, the failure is in binding the occluded object to its container, not specifically in composing identical-object swaps.

## Addendum C: horizon set (G2), written 2026-09-23 before running any model on it

### Motivation

This addendum comes from exploratory results on opaque3, which are not confirmatory:
- the state after the first swap is decodable (0.86–0.92, at the last token and on the video tokens right after swap 1);
- no later state is decodable (chance).

### Data

`data_horizon/` (`scripts/tracking_algo_horizon.py`, seed 20260926), 720 videos, 90 per condition.
- A mid-sequence "reveal" lifts all cups and shows the ball.
- m = number of swaps since the last sighting of the ball.

### Hypothesis

**H5, one-update horizon**: the final state is linearly decodable from the model's hidden states if and only if m = 1.
- Decoding is done from the last-token hidden state, 5-fold CV per condition, at each model's best layer from the opaque3 analysis: Qwen3-VL-8B L24, Qwen3.5-9B L18.
- Predictions:
  - K3_m1 and K4_m1: decodability > 0.7;
  - K3_m2, K3_m3 and K4_m4: decodability ≈ majority rate (< 0.5).
- Falsified if K3_m2 decodes as well as K3_m1, or if K3_m1 is at chance.
  - The first case would mean the horizon is not one update.
  - The second would mean S1 was special because it was the first swap in the video, not because it came right after a sighting.

### Delay check (exploratory)

K1_w0/w2/w4 test whether the one-update state survives 2–4 s of occlusion before the swap, i.e. latent maintenance rather than an iconic trace.

### Native answers

Reported per condition, exploratory.

## Addendum D: binding set, written 2026-09-23 before running any model on it

### Result from Addendum C (both models)

- H5 is falsified.
  - After a single swap that follows a mid-video reveal (K3_m1, K4_m1), the final state is near chance.
  - After the video's first swap it is decodable (Qwen3-VL last token L24: 0.97–0.98, even after a 2–4 s delay).
- The re-sighted position itself is decodable during the reveal and after lowering (≈1.0).

### Data

`data_binding/` (seed 20260927), 150 per condition. Exactly one swap moves the ball; distractor swaps exchange the other two cups.
- B_ball_first: ball swap, then distractor.
- B_dist_first: distractor, then ball swap.
- B_dist2_first: two distractors, then ball swap.

### Hypothesis H6 (first-event binding)

Last-token decodability of the final state (Qwen3-VL L24, Qwen3.5 L18; 5-fold CV) is > 0.7 for B_ball_first and near chance (< 0.5) for B_dist_first and B_dist2_first.

The alternative, "one effective update": all three conditions are > 0.7.

## Addendum E: interference set (replaces the invalid Addendum D test), written before any model run

### Data

`data_interference/` (seed 20260929), 3 opaque cups, 150 per condition. The target swap is a random pair, so the final state is a non-linear conjunction of the initial position and that pair.

Symbolic additive baselines (init + involvement counts, or init + per-swap pair one-hots) are 0.33–0.55, so linear shortcuts are excluded.

| condition | sequence |
|---|---|
| E_R | reveal, random swap |
| E_WR | reveal, 1.25 s wait, random swap |
| E_DR | reveal, distractor swap of the two non-ball cups, random swap |

### Hypothesis H7 (first-event-only update)

Last-token decodability of the final state (Qwen3-VL L24, Qwen3.5 L18; 5-fold CV) is:
- \> 0.7 for E_R and E_WR;
- < 0.5 for E_DR.

### Alternative ("first ball-relevant update")

E_DR is also > 0.7. The distractor leaves the ball in place, so E_DR has only one relevant update.

We also report the video-token group right after the last swap.

## Addendum F: second-update set, written before any model run

### Result from Addendum E

H7 is falsified. A preceding distractor swap does not block the update: for Qwen3-VL at last-token L24, E_DR = 0.98, E_R = 0.99 and E_WR = 0.99.

### Data

`data_second/` (seed 20260930, `SET=F scripts/tracking_algo_interference.py`), 3 opaque cups, 150 per condition. Per-swap symbolic baselines are 0.34–0.54.

| condition | sequence |
|---|---|
| F_MVR | reveal, ball-moving swap, reveal, random swap |
| F_MR | reveal, ball-moving swap, random swap |
| F_DVR | reveal, distractor, reveal, random swap |

### Hypothesis H8 ("one ball-move per video; re-sighting does not reset it")

Last-token decodability of the final state (Qwen3-VL L24, Qwen3.5 L18):
- F_DVR > 0.7;
- F_MVR < 0.5;
- F_MR < 0.5.

### Alternative ("a re-sighting resets tracking")

F_MVR > 0.7.

## Addendum G: causal activation patching (Qwen3-VL-8B), written before running

### Data

`data_patch/` (seed 20261002), 480 videos: reveal plus one random swap, with identical timing and token layout.
- The first 240 fit frozen linear probes of the final state from the last-token hidden (L24 and L36), unpatched.
- The last 240 are targets.

### Intervention

- Pairing: each target B gets a source A with the same initial position and a different final state. A control source has the same final state as B.
- At residual layer l ∈ {8, 16, 24, 32}, B's video-token activations are overwritten with A's on three position sets:
  - `post`: groups after the swap;
  - `mid`: groups during the swap;
  - `all`: every video token.
- Readouts: probe prediction and the native option-letter logits.

### Hypotheses

- **H9 (state carried on the video tokens and read by the last token)**: for at least one l ≤ 24, `post` patching makes the L24 probe predict the SOURCE state in > 70% of pairs, while the same-state control leaves the probe at its unpatched accuracy (±10 pts).
- **H10 (readout gap)**: under the same `post` patch, the native answer switches to the source state in < 20% of pairs. The source-minus-target logit margin shift is reported with a bootstrap CI.
